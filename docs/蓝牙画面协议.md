# 蓝牙画面协议 v1

Windows 作为 BLE GATT 外设。iPhone 广播扩展作为 BLE 中心连接 Windows，使用带确认的加密特征写入。日常画面与输入均不使用网络服务器或 Wi-Fi。

## 服务

| 含义 | UUID |
| --- | --- |
| 画面服务 | `72d00001-7b56-4a5e-9f12-8c454e50424c` |
| 画面数据写入 | `72d00002-7b56-4a5e-9f12-8c454e50424c` |
| 版本及电脑名称读取 | `72d00003-7b56-4a5e-9f12-8c454e50424c` |

独立的标准 HOGP 服务为 `0x1812`，键盘 Report ID 为 1，鼠标为 2。HOGP 通知值不附加 Report ID 字节，ID 由各特征的 Report Reference 描述符表达。

## 每包公共头

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 2 | ASCII `LP`，十六进制 `4c 50` |
| 2 | 1 | 版本 1 |
| 3 | 1 | 类型：1 开始，2 数据，3 结束 |
| 4 | 4 | 帧 ID，uint32 小端 |
| 8 | 4 | 数据偏移，uint32 小端 |

开始包额外包含 JPEG 总长度 uint32 和 CRC32 uint32，共 20 字节。数据包携带连续 JPEG 字节。结束包长度 12，偏移等于总长度。CRC32 使用多项式 `0xedb88320`，初值与最终异或均为 `0xffffffff`。

每个带确认的写入等待确认后才发送下一个。分片上限同时参考 iOS 的有响应和无响应最大写入长度，避免误用 512 字节长写入而触发 ATT prepared write。协议也支持只有 20 字节写入容量的连接，但吞吐会很低。

Windows 仅接受当前选中设备的写入。每次只保留一个未完成帧，上限 256 KiB，接收过程超过 30 秒作废；检查偏移、长度、CRC32 和 JPEG 尺寸后才显示。UI 只保留一份待显示画面，避免排队堆积。

iPhone 扩展同时最多保留一个待编码或发送的采样帧。初始编码最长边 640 像素、JPEG 质量 0.35；每帧结束后至少等待半秒，实际速率还受链路和编码速度限制。这些是实验参数，不是实测性能承诺。

编码仅在加密连接完成版本确认后开始。每帧持有独立生命周期标识；暂停会使既有帧失效，恢复后不会续发暂停前的画面。停止广播会同步关闭采样入口，已经排队的编码结果也不能继续发送。Swift 协议与生命周期测试已在标准 macOS 构建机上执行并通过；真实设备的画面传输仍需验证。
